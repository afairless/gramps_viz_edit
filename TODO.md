| 7 | `feat: add Pass 1 matcher with exact handle + fuzzy content matching` | Matcher module | `crates/diff/src/matcher.rs` — `match_graphs(graph_a: &Graph, graph_b: &Graph, schema: &Schema) -> MatchResult`. Pass 1a: exact handle match between the two graphs → SAME (identical fields) or MODIFIED (different fields). Pass 1b: fuzzy content match for unmatched items using per-type strong and weak match keys. Produces handle map (`HashMap<Handle, Handle>`, direction: B-handle → A-handle) and `Vec<ItemDiff>` with classifications SAME, MODIFIED, ADDED, REMOVED, NEEDS_REVIEW. Large-graph optimization: unmatched items indexed by strong match key for O(1) lookup instead of O(n×m) pairwise comparison. Exposes `MatchResult { handle_map: HashMap<Handle, Handle>, item_diffs: Vec<ItemDiff>, ambiguous_cases: Vec<AmbiguousCase> }`. Uses `compare` module for field-level comparison, `similarity` + `normalize` modules for fuzzy matching. Per-type match keys: Person → strong (primary_name.surname + primary_name.first_name + birth date), weak (gramps_id, alternate names, death date, birth place); Family → strong (father_handle + mother_handle), weak (gramps_id, child_ref_list); Event → strong (event_type + date + description), weak (gramps_id, place_handle); Place → strong (name.city + name.street), weak (gramps_id, place_ref_list); Source → strong (title), weak (gramps_id, author); Citation → strong (source_handle + page), weak (gramps_id, confidence); Repository → strong (name), weak (gramps_id, type_field); Media → strong (path + checksum), weak (gramps_id, desc, mime_type); Note → strong (text), weak (gramps_id, type_field); Tag → strong (name), weak (gramps_id, color). | Unit (exact handle match → SAME, one-field diff → MODIFIED, fuzzy match by name+birth → SAME/MODIFIED, no match → REMOVED/ADDED, ambiguous → NEEDS_REVIEW with candidates; edge cases: Person with no name fields → no fuzzy match possible, Person with Unicode-only name → matched by normalized Unicode comparison via `diacritic_insensitive_eq`, empty graphs for a given type → all ADDED/REMOVED, duplicate strong match keys → NEEDS_REVIEW with multiple candidates, large graph with O(1) key index path) |
